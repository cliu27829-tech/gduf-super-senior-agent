# 管理员使用说明

## 首次登录

管理员仅由部署环境变量在首次启动时引导创建。打开 `/login`，使用 `ADMIN_BOOTSTRAP_EMAIL` 登录，立即在个人中心修改密码。后台入口是 `/admin`；普通用户即使直接输入 URL，也会被前端跳转和后端 403 双重阻止。

## 核心规则

- `verified` 不是装饰标签：地点、饭堂、档口和流程标为已核验时必须填写 `evidence`，并建议填写核验备注、时间、方法和来源。
- 历史数据不可机械改成年份更新；无法证明时使用 `needs_verification` 或 `expired`。
- 常见餐品不等于今日菜单；不要把模型输出录入为事实。
- 用户纠错是线索，批准表示进入维护流程，不自动让地点变成已核验。

## 后台模块

- 仪表盘：用户、地点、饭堂、待审纠错、陈旧记录与近 7 日错误。
- 用户：启用/停用与角色管理；无法查看密码、Token、API Key。
- 校区/地图/饭堂/档口/流程/来源：结构化 JSON 新增和编辑，后端再次用 Pydantic 校验。
- 地点：表单新增、核验证据、示意坐标和停用。
- 纠错：批准或拒绝，填写审核备注。
- 过期数据：列出 180 天未核验或从未核验的地点。
- 日志：审计、系统错误、数据刷新记录。
- 导入导出：地点 CSV/JSON/GeoJSON，最大 5 MB；导入不自动变为已核验。

## 数据更新流程

1. 取得学校官网、校区公告、现场照片/记录或审核后的学生线索。
2. 新建/更新 `sources`，填发布、获取与核验时间。
3. 在实体中选择校区、来源、状态、可信度和启用状态。
4. 若标为已核验，填写可追溯证据与备注。
5. 保存后检查前台来源卡片与更新时间。
6. 在系统日志确认审计记录，必要时导出备份。

## 学生纠错流程

学生在地点抽屉提交内容 → 后台“纠错审核”出现 pending → 管理员核实证据 → 更新地点 → 批准/拒绝纠错并写备注 → 前台刷新看到新记录。纠错正文不进入系统错误日志。
