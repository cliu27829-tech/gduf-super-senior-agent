# 全栈重构报告

## 结果

项目已从单进程 Streamlit 演示迁移为 React + FastAPI + PostgreSQL 标准网站。正式入口不再依赖 `streamlit run app.py`；旧代码保存在 `legacy_streamlit/`，便于追溯和继续迁移，不参与新站运行。

## 复用内容

复用了原项目的中国时间语义、通知提取规则、ICS 双提醒、地点与饭堂数据结构、三校区配置、来源/新鲜度模型、Agent 工具边界和历史数据。新代码重写了身份、持久化、API、页面状态、权限和部署层。

## 新增能力

- 正式账号、Argon2、JWT Cookie、Refresh 撤销、账户隔离与 RBAC。
- PostgreSQL 模型、Alembic 初始迁移、Docker Compose。
- React 响应式 11 个用户/后台主页面与细分后台路由。
- 结构化 Agent 响应、对话历史、工具与来源卡片。
- 通知只预览不写库、确认后任务持久化、可自定义 ICS 提醒。
- 三校区地图/饭堂页面、外部导航、纠错审核与核验证据。
- 管理实体、审计/系统/刷新日志、陈旧列表、数据导入导出。
- 后端 32 项、前端 13 项测试和全栈 CI。

## 关键取舍

选择 Vite React 而非 Next.js，因为当前页面全部由后端 API 驱动，不需要服务端渲染，静态前端可由 Nginx/Vercel 独立发布。选择同步 SQLAlchemy 以降低迁移复杂度，接口边界仍可横向扩展。SQLite 保留为测试便利，正式 Compose 使用 PostgreSQL。

没有实现 OCR、实时菜单、校内路线、邮件/Push、微信登录等 P2 能力；这些能力需要可靠外部数据或基础设施，不能用模型或占位实现冒充。

## 待发布事项

需要用户在一个部署平台完成登录，随后创建托管 PostgreSQL、配置生产 Secrets、部署并按在线清单冒烟。真实三校数据仍需人工核验，不属于代码生成可以替代的工作。
