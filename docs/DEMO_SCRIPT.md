# 广金大师兄 Demo 脚本

## 准备

1. 执行 `python -m streamlit run app.py`。
2. 不填 API Key，以验证本地工具降级路径。
3. 在首页选择“广州校本部”。
4. 向观众说明：内置地点是历史线索/待核验 Demo，目的是展示数据诚实机制，不声称点位已完整。

## 场景一：地点搜索

输入：

> 广州校本部有哪些饭堂？

预期：

- 路由到 `canteen_search`，工具计划显示 `list_canteens` 和 `get_canteen_details`。
- 只显示广州校本部，不混入肇庆/清远。
- 每个饭堂显示所在位置、楼层、已核验档口（如有）、营业时间、支付方式、数据状态、核验时间、置信度、来源和导航。
- 历史/待核验数据有明显警告。

然后打开“校园地图”：

- 切换三校并观察数据不混用。
- 使用“只看饭堂”、分类、搜索和“按已知地点查附近”。
- 展开地点详情，查发布/抓取/核验时间、来源等级、置信度和导航。

## 场景二：餐饮搜索

输入：

> 我想吃面，哪个饭堂有？

预期：

- 路由到 `food_search`。
- 只查询已核验且不是 `demo_fixture` / `unverified_seed` 的档口。
- 默认种子数据没有这类可靠档口，因此系统应明确说无可用已核验数据，并说明不会编造今日供应。
- 管理员在后台新增并实地核验“面食”档口后，再问同一问题，系统应返回饭堂/档口/楼层/常见餐品/最后核验，并附“不保证今日营业”警告。

## 场景三：通知变任务

粘贴：

> 申请表提交
>
> 截止：9月3日下午5点
>
> 地点：北教
>
> 材料：申请表、学生证
>
> 提交方式：纸质版

预期：

1. 提取任务草稿，显示名称、截止、地点、材料、提交方式和年份推断说明。
2. 未勾选“我已核对”时保存按钮不可执行，数据库中无新任务。
3. 确认后创建 SQLite 任务，下载文件名含随机后缀的 ICS。
4. ICS `DTSTART` 带 `Asia/Shanghai` 时区。
5. 任务中心可看到来源和待办状态。

## 场景四：持续追踪

输入：

> 我这周还有什么没完成？

预期：

- 路由到 `task_management` 并按当前 `user_id` 查 SQLite，不使用模型记忆伪造状态。
- 在任务中心标记完成后重问，已完成任务不再出现于“本周未完成”。
- 用另一个 `user_id` 查询时不能看到原用户任务。

## 后台补充演示

- 创建/编辑地点与饭堂，查看更新前版本。
- 创建/编辑饭堂档口，修改餐品、餐段、营业时间和支付方式。
- 上传校园底图，上一张自动停用但记录保留。
- 强制刷新一个官方源，观察发布日期、抓取时间、内容变化和错误保留状态。
- 停用错误地点/档口，以及回滚地点的上一版。
