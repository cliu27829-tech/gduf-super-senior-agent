# 数据来源与更新机制

## 来源优先级

1. 学校官网与校区官网。
2. 学校职能部门官网。
3. 学校官方微信公众号。
4. 学校公开后勤或服务公告。
5. 管理员实地核验。
6. 审核通过的学生提交。
7. 普通公开网页。
8. 未核验历史资料。

优先级不等于新鲜度。一篇旧的官方页面仍可能是 `historical`，不能因为域名官方就声称是当前事实。

## 内置官方源配置

`data/official_sources.json` 当前配置：

- 广州校本部：广东金融学院官网、广东金融学院后勤服务中心。
- 肇庆校区：广东金融学院肇庆校区网站。
- 清远校区：广东金融学院清远校区网站。

配置只说明“可刷新的公开源”，不说明网页中的所有字段已被人工核验为地点事实。

## 刷新流程

1. 按校区过滤来源。
2. 检查 6 小时缓存；管理员可强制刷新。
3. 使用连接/读取超时、最多两次重试和退避。
4. 解析页面标题、纯文本和可识别的发布日期。
5. 计算 SHA-256 内容哈希，记录 `updated` 或 `unchanged`。
6. 失败时记录 `failed` 或 `failed_preserved`，保留上一版文本与哈希。
7. 变化内容只进入来源缓存和待核验提示，不直接覆盖已核验地点。

## 原历史资料

`/ 好人师兄` 中的文件已保留。运行时加载器会：

- 提取文件中的年份和 URL。
- 识别 `gduf.edu.cn` 官方域名，但不把域名自动等同于当前有效。
- 最新可解析年份早于运行时年份时，标为 `historical` / `expired`。
- 没有可解析年份时，标为 `needs_verification` / `unknown`。
- 将文件名、来源 URL 和时效警告一起放入检索上下文。

原资料中的图片没有被自动 OCR 成当前事实。图片中信息需要人工核验和版权检查。

## 纠错与导入

用户纠错只写入 `user_location_feedback` 的 `pending` 状态，不会自动修改官方数据。后台支持 CSV、JSON、GeoJSON 导入；同 ID 更新前先创建 `location_versions` 快照。错误地点和档口采用逻辑停用，保留审计痕迹。
